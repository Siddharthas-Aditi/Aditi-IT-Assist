# Playbook: Database Migrations

**When**: any change to `app/models/*` or the DB schema. Current head: `009`; next is `010`.

## Approach
1. Change the SQLAlchemy model in `app/models/` (and export from `models/__init__.py`).
2. Generate the migration: `make db-revision MSG="short description"`. Review the
   autogenerated ops — Alembic misses some changes (server defaults, enum edits, indexes).
3. Write a **real, tested `downgrade`**. Both directions must run cleanly.
4. pgvector: mark chunks `indexed` only when a vector exists (`pending` otherwise);
   provide/adjust backfill (`scripts/backfill_embeddings.py`) for populating existing rows.
5. Update Pydantic schemas if the shape is exposed via API; bump any typed contract
   version (`SCHEMA_VERSION`, `HandoffPackage`, registry `*_VERSION`).
6. Update `memory/domain-model.md` + relevant `docs/architecture/*` (`data-model.md`,
   `retrieval-and-indexing.md`).

## Validate
```bash
make db-migrate        # apply upgrade
make db-downgrade      # verify downgrade works
make db-migrate        # re-apply
make seed              # seeds still work
make test-backend
```
On a scratch DB, confirm 002→010 applies contiguously from empty.

## Checklist
- [ ] Migration id is next in sequence; history not rewritten.
- [ ] `downgrade` implemented and tested.
- [ ] Contract versions bumped; schemas updated.
- [ ] Backfill provided if new non-null/embedding columns.
- [ ] `memory/domain-model.md` + docs updated.

## Never
Edit an already-applied migration to change history — add a new one. Assume embeddings
exist. Add a non-null column with no default/backfill on a populated table.
